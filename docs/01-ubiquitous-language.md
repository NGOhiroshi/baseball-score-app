# ユビキタス言語辞書

> **このドキュメントの目的**
> プロジェクト関係者（長尾さん、将来の協力者、そしてClaudeも）が同じ言葉を同じ意味で使うための辞書。コード上の変数名・クラス名・テーブル名もこの辞書に従う。
>
> **DDD的位置づけ**
> DDDの出発点。「打席」と「打数」を区別しないとドメインモデルが破綻する。**コード・ドキュメント・会話で使う言葉を統一する**のがユビキタス言語の本質。

---

## 1. チーム・人に関する用語

| 用語 | 英語表記（コードで使用） | 定義 |
|---|---|---|
| チーム | `Team` | アプリを利用する草野球チーム。MVPでは「スミスブラザーズ」のみ。Phase 2でマルチテナント化 |
| メンバー | `Member` | チームに継続的に所属する選手。事前にプロフィール登録される |
| 助っ人 | `GuestPlayer` | 試合当日だけ参加する選手。簡易登録のみ（写真や詳細プロフィール不要） |
| 選手 | `Player` | メンバーと助っ人の総称（試合で打席に立つ人）。コード上は抽象概念 |
| 管理者 | `Admin` | チーム情報の編集や機密情報閲覧ができる権限を持つメンバー |
| 一般メンバー | `RegularMember` | 通常の閲覧・スコア入力権限を持つメンバー |

> 💡 **「メンバー」と「選手」を分けた理由**: 助っ人は「メンバーではない選手」だから。試合の打順登録では「選手」という抽象を扱い、その実体が「メンバー」か「助っ人」かを区別する。

## 2. 試合に関する用語

| 用語 | 英語表記 | 定義 |
|---|---|---|
| 試合 | `Game` | 1回の対戦。試合日・対戦相手・イニングスコアを持つ |
| 対戦相手 | `Opponent` | 相手チーム名。文字列のみ（システム上のチームとして管理しない） |
| 打順 | `BattingOrder` | 試合開始時の1〜9番（または可変）の打席順。各打順に1名の選手が紐づく |
| イニング | `Inning` | 試合内の区切り。1〜9回、表（自チーム攻撃）/裏（相手攻撃）の区別あり |
| イニングスコア | `InningScore` | 各イニングごとの自チーム得点・相手得点（スコアボード上の数字）。例: 1回 0-1, 2回 2-0 ... |
| 最終スコア | `FinalScore` | 全イニングの合計。**イニングスコアから自動計算され、独立しては持たない** |

## 3. 打席結果に関する用語（**ドメインの中核**）

### 3.1 上位カテゴリ（必ずどれか1つ）

| 用語 | 英語表記 | 定義 |
|---|---|---|
| 打席 | `PlateAppearance` | 選手が打席に立った1回の機会。結果が必ず1つ紐づく |
| 安打 | `Hit` | バットで打ち、野手の守備機会を経ずに出塁すること |
| 出塁 | `Walk` / `ReachedOnBall` | 四球・死球による出塁。本辞書では「四死球」を含む包括カテゴリ |
| 凡退 | `Out` | アウトになること（三振・ゴロ・フライ） |
| 犠打/犠飛 | `Sacrifice` | 走者を進めるためのバント、または走者を生還させた外野フライ。アウトになるが**打数に含めない** |
| 失策のみ | `ErrorOnly` | 守備のミスにより出塁。安打ではない |

> ⚠️ **重要ルール**: これらの上位カテゴリは**排他的**。1打席は必ずどれか1つに分類される。
> ただし「安打」のみ、「失策フラグ」を同時に立てることが可能（後述）。

### 3.2 下位カテゴリ

#### 安打の種類
| 用語 | 英語表記 | 定義 |
|---|---|---|
| 単打 | `Single` | 1塁打 |
| 二塁打 | `Double` | 2塁打 |
| 三塁打 | `Triple` | 3塁打 |
| 本塁打 | `HomeRun` | ホームラン |

#### 出塁の種類
| 用語 | 英語表記 | 定義 |
|---|---|---|
| 四球 | `BaseOnBalls` (BB) | ボール4つで出塁（俗称: フォアボール） |
| 死球 | `HitByPitch` (HBP) | 投手の投球が体に当たって出塁（俗称: デッドボール） |

#### 凡退の種類
| 用語 | 英語表記 | 定義 |
|---|---|---|
| 三振 | `Strikeout` | ストライク3つでアウト |
| ゴロ | `GroundOut` | 打球がゴロで野手に処理されてアウト |
| フライ | `FlyOut` | 打球がフライで野手に捕球されてアウト |

#### 犠打/犠飛の種類
| 用語 | 英語表記 | 定義 |
|---|---|---|
| 犠打（バント） | `SacrificeBunt` | 走者を進塁させるための意図的なバントでアウト。**打数に含めない**、安打にはならない |
| 犠飛（犠牲フライ） | `SacrificeFly` | 走者（通常は3塁走者）を生還させた外野フライ。**打数に含めない**、安打にはならない、**打点が付く** |

> 💡 **集計ルール**:
> - 犠打・犠飛は「打席数」には含めるが、「打数」からは除外する（出塁の四死球と同じ扱い）
> - 安打数・打率には影響しない
> - 犠飛では「打点」フィールドに値が入る（手動入力）

### 3.3 失策（特殊な扱い）

| 用語 | 英語表記 | 定義 |
|---|---|---|
| 失策 | `Error` | 野手のミスで打者が出塁した、または進塁を許したケース |

> 🚨 **草野球特有のルール**: 「安打 + 失策」の同時記録を許可する。「ワンヒット・ワンエラー」の状況に対応するため。
> - **記録上は安打として集計**する（打率・安打数は加算）
> - 失策フラグは別途立てておく（守備側の失策数集計用）
> - 「失策のみ（=安打ではないが守備のミスで出塁）」のケースも存在

### 3.4 打球方向・守備位置

| 用語 | 英語表記 | 定義 |
|---|---|---|
| 打球方向 | `BattingDirection` | 安打/失策時の打球の飛んだ方向（例: レフト前、センターオーバー） |
| 守備位置 | `FielderPosition` | 凡退時のゴロ・フライを処理した野手の位置（1〜9: 投/捕/一/二/三/遊/左/中/右） |

## 4. 打撃成績の用語

| 用語 | 英語表記 | 定義 | 計算式 |
|---|---|---|---|
| 打席数 | `PlateAppearances` | 打席に立った総数 | 全打席を数える |
| 打数 | `AtBats` | 公式打数。打席から四死球・犠打・犠飛を除いた数 | `打席数 − 四死球 − 犠打 − 犠飛` |
| 安打数 | `Hits` | 安打の総数 | 安打を数える（失策との重複ケースも含む） |
| 打率 | `BattingAverage` | 打撃の率 | `安打数 ÷ 打数`（小数3桁、例: .350） |
| 打点 | `RunsBattedIn` (RBI) | 自分の打席で本塁を踏ませた走者の数 | **手動入力**（走者状況は記録しないため） |
| 得点 | `RunsScored` | 自分が本塁を踏んで得点した回数 | **手動入力** |
| 本塁打数 | `HomeRuns` | 本塁打の総数 | 安打のうち本塁打を数える |

> 💡 **MVPの判断**: 打点・得点は手動入力。理由は「走者状況を記録しない」ため自動計算できないから。記録UIで打席結果と同時に入力できるようにする。

## 5. 投手成績の用語

| 用語 | 英語表記 | 定義 |
|---|---|---|
| 登板 | `PitchingAppearance` | ある投手が試合で投球した区間（先発・継投・救援） |
| 投手交代 | `PitcherChange` | ある登板の終了と次の登板の開始 |
| 投球回 | `InningsPitched` (IP) | 投手が投げたイニング数。**X.Y回（Y は 0/1/2 アウト）の形式**（例: 5.2回 = 5回と2アウト） |
| 奪三振 | `Strikeouts` (K) | 投手が三振を奪った数 |
| 与四死球 | `WalksAllowed` (BB+HBP) | 投手が許した四球と死球の合計 |
| 失点 | `RunsAllowed` (R) | 投手が許した相手の得点 |
| 自責点 | `EarnedRuns` (ER) | 投手の責任に帰す失点（失策による得点を除く） |
| 防御率 | `EarnedRunAverage` (ERA) | 9イニングあたりの自責点 |

### 計算式
- 投球回（X.Y形式 → 数値変換）: `IP = X + Y/3`
- 防御率: `ERA = (自責点 × 9) ÷ 投球回`

| 被安打 | `HitsAllowed` (H) | 投手が許した安打数 |

> 💡 **入力UXの方針（長尾さんとの合意）**:
> 投手成績は **「イニング終了時に1イニング分をまとめて入力」** する UI とする。
> 入力対象（1イニングあたり）: 失点・自責点・四死球・奪三振・**被安打**。
> 自責点 vs 失点 の判定は記録者（長尾さん）が現場で判断し、別々に手動入力する。
> このUXを反映するため、ドメインモデルでは `PitchingAppearance` の子エンティティとして `InningPitched`（イニング単位の記録）を持たせる（詳細は `03-domain-model.md` 参照）。

## 6. 用語の使い方ルール

1. **コードでは英語表記を使う**: `class Hit`, `function calculateBattingAverage()` など
2. **画面表示は日本語**: ユーザーは草野球プレイヤー。「Hit」より「安打」が分かりやすい
3. **テーブル名はスネークケース英語**: `plate_appearances`, `pitching_appearances`
4. **辞書にない言葉を新規に使うのは禁止**: 新概念が必要なら、まずこの辞書に追加してから使う
5. **意味が曖昧な言葉は辞書を更新**: 例えば「ヒット」と「安打」が混在したら、どちらかに統一して辞書を直す
